# The document model, first contact — the drive sheet, 2026-09-13

Phase 2 of v2.1 turned a project from a row in a database into a file you open and save
([#37](https://github.com/matheus-sancha/FlowMap/issues/37)). **Nothing in the suite renders a
pixel**, and this phase added 61 tests that still do not: the format, the loader, the lock, the
autosave, the conversion and the recent list are all proved headlessly. **Not one of the things
below has ever been seen.**

This sheet is shorter than the last two on purpose. It covers one change, and the change is
load-bearing: if opening a document is wrong, nothing after it matters.

## Read this before launching

**Back the database up first, by hand, and check the backup exists.** Phase 1 writes
`flowmap.pre-v31.sqlite` automatically on the first launch after the upgrade — that is one of the
things being tested here — but do not rely on the thing under test to be the thing that saves you.

**Section 1 is the conversion and it happens once.** It runs on the first launch and never again, so
if it is wrong there is no second chance to watch it. Read section 1 before opening the app at all.

**This is the first sheet where the checks write files outside the app's own folder.** Sections 3
and 5 create documents; delete them afterwards or leave them, but know they are there.

**Opening is explicit, on purpose, and that is temporary.** The app has been decided to reopen the
last document on launch when it still exists and nobody holds the lock — it is **not built yet**, and
this sheet is deliberately walked without it. Auto-reopen would change what checks 5, 10, 22 and 23
show, and the mechanism is worth seeing before a convenience is laid over it. *"I had to open it
every time"* is expected here, not a finding.

**Do not use the real plant for section 5.** Use a copy. That section is about what happens when two
people open one document, and the way to test it is to make a copy and open that from a second
place.

## 1 — The conversion, which happens once

The one-way move of real data. It ran clean against a copy; it has never run for real.

1. **The backup is there before anything else.** Open the data folder and confirm
   `flowmap.pre-v30.sqlite` exists and is about 170 MB. **If it is not there, stop** — everything
   below writes to a database that has no way back.
2. **`VSM 2026 Q1.flowmap` appears in `Documents\FlowMap`.** About 29 KB. Confirm the folder was
   created and the file is there.
3. **It appears in Recent on the start screen**, named *VSM 2026 Q1* — the project's name, not the
   file's.
4. **Nothing was destroyed.** The conversion only writes. If step 2 produced nothing, the database
   is still intact and untouched; say so rather than assuming.
5. **Restarting does not do it again.** Close and reopen. There must be exactly one
   `VSM 2026 Q1.flowmap` and no `VSM 2026 Q1 (2).flowmap`.

## 2 — Opening, and what a project looks like when it is a file

6. **The start screen is what you meet.** No project open, an explanation, *Open…* and *New
   project…*, and the Recent list. The old projects list is gone; say whether anything is missed.
7. **Open the converted document.** Every study, order and workcenter is where it was: 3 studies,
   250 orders, 42 workcenters, the thresholds at 85/100 and float at 0/30.
8. **The save indicator reads `saved <time>`** under the nav rail. It is the only save vocabulary in
   the app and there is no Save button anywhere — confirm that reads as deliberate rather than as
   missing.
9. **Change something small** — a project name, a threshold — and watch the indicator go to
   *saving…* and back within a few seconds. Then confirm the file's timestamp moved.
10. **Close the app with an edit seconds old.** Reopen. The edit is there. This is the one that
    decides whether "no Save button" is safe.
11. **Resources with nothing open.** Close the document (or start fresh) and open Resources. It
    shows the **library** — the seeded types and patterns, no plant. Say whether that is
    understandable or just looks empty and broken.

## 3 — A new project

12. **New project… asks where to put it**, and the file lands there with the name you typed.
13. **It contains the seeded reference data and nothing else**: the nine workcenter types, the shift
    patterns, one plant, no workcenters, no studies. Confirm that is a usable starting point rather
    than a dead end — this is the check most likely to say *"I cannot do anything from here"*.
14. **The project is named after the file.** Confirm you were not asked twice for the same name.
15. **A reference plant comes from Open + Save As** — which does not exist yet (phase 3). Confirm
    that gap is tolerable for now, or that it is not.

## 4 — Runs, which are not in the document

16. **Run a simulation.** It completes and the results are as before.
17. **The document did not grow.** Check the file size before and after: ~29 KB either way. Runs
    stay on this machine by design; a document that carried them would be 170 MB.
18. **The save indicator did not flicker** while the run was written. Hundreds of thousands of rows
    landed and none of them is the document's business.
19. **Close and reopen the document. The run is still listed.** This is what schema v32 was for — a
    run belongs to the document id, not to a project row that gets emptied on every open.

## 5 — Two people, one document

*Use a copy of the document, not the real one.*

20. **Put a copy on a shared drive or in OneDrive** and open it from there. It opens, and editing
    saves to that location.
21. **A second opener is told who has it.** With the document open, try to open the same file again
    (a second machine if you have one; otherwise a second copy of the app). The message names a
    person and a machine, and offers a read-only copy rather than a way to force it.
22. **`<name>.flowmap.lock` sits beside the document** while it is open, and **is gone after the app
    closes**.
23. **A crash leaves nothing permanent.** Kill the app with the document open (Task Manager). The
    lock file survives. Wait five minutes, open the document again — it opens, with no dialog asking
    anyone to break anything. **This is the check the whole lock design turns on**: if it does not
    heal, a crashed colleague blocks a file until someone intervenes.
24. **A document on a disconnected drive is still listed.** Disconnect the share or pause OneDrive.
    The Recent entry stays, marked *not found right now*, and says the file may be on a drive that is
    not connected. It must not vanish.

## 6 — What it says when it goes wrong

25. **Open something that is not a FlowMap document** — rename any file to `.flowmap`. The message
    says what the file is, in a sentence, and the app stays usable.
26. **Save to somewhere that has gone away.** With a document open from a share, disconnect it, then
    edit something. The indicator turns to *could not save* and says the work is safe in FlowMap and
    the file is what could not be written. **The edit must still be in the app** — check the value
    you typed is still there.
27. **Reconnect and edit again.** It saves, and the indicator recovers.
